UniDesk — Ứng dụng web quản lý sinh viên

Bộ mã nguồn mới, độc lập với dự án cũ. Backend Spring Boot, frontend React; giao diện sáng, menu bên trái, bảng quản lý và ba vai trò theo hướng của PDF tham khảo. Dùng logo HaUI theo yêu cầu cho bản đồ án; tên ứng dụng vẫn là UniDesk.

Cách nhanh nhất: giải nén toàn bộ ZIP, chạy CHAY-UNG-DUNG.cmd, đợi dòng Started Application, rồi mở http://localhost:8081. Cần Java 17 trở lên; khuyến nghị dùng JDK 21 cho môi trường phát triển. Bản JAR đã kèm giao diện: không cần npm, Maven hay MySQL cho lần chạy thử này.

Đọc HUONG-DAN-WINDOWS.html bằng Chrome để xem hướng dẫn có định dạng, hoặc docs/HUONG-DAN.md để xem đầy đủ lệnh chạy, MySQL và cách sửa mã nguồn.

Giảng viên gv001 Teacher@2026Demo

Đây là dữ liệu thử. Tài khoản mẫu được tạo một lần khi database còn trống. Đổi mật khẩu không làm mất dữ liệu. Các tài khoản do ADMIN tạo hoặc reset sẽ bắt buộc đổi mật khẩu trước khi dùng hệ thống.

Các tệp chính

  • backend/: mã Java, cấu hình, migration SQL, kiểm thử tự động và Maven Wrapper.
  • frontend/: mã React, CSS, cấu hình Vite và package-lock.json.
  • release/student-manager-2.0.0.jar: bản đã build, chứa cả giao diện và backend.
  • database/TAO-DATABASE.sql: tạo database và user riêng cho MySQL.
  • CHAY-UNG-DUNG.cmd: chạy ngay với database H2 lưu trên ổ đĩa.
  • CHAY-MYSQL.ps1: chạy bản JAR với MySQL và hỏi mật khẩu tại terminal.
  • BUILD-LAI.cmd: build lại frontend, chạy kiểm thử backend và đóng gói JAR mới.
  • docs/CHUC-NANG-VA-QUY-TAC.md: phạm vi chức năng và quy tắc nghiệp vụ.
  • docs/KIEM-THU.md: kết quả kiểm tra và kịch bản demo.
  • docs/API.md: danh sách API.

Không ghi đè thư mục dự án cũ. Cơ sở dữ liệu cũ không được tự động chuyển sang cấu trúc này.

Bản cập nhật HaUI + Render

Logo HaUI và cỡ chữ lớn hơn đã được build vào bản chạy sẵn. Xem HUONG-DAN-RENDER.html để cập nhật dữ liệu cũ, sửa giao diện và triển khai Render + Aiven MySQL từng bước. Mã nguồn cấu hình: Dockerfile, render.yaml, deploy/start-render.sh, backend/src/main/resources/application-render.properties.

Hướng dẫn chạy trên Windows

1. Chuẩn bị và giải nén

Giải nén toàn bộ ZIP, ví dụ thành D:\student-manager-v2. Không mở chương trình từ bên trong cửa sổ ZIP. Giữ nguyên cấu trúc các thư mục.

Mở PowerShell và kiểm tra:

java -version

Bản chạy sẵn cần Java 17 trở lên. Dự án được biên dịch với mức tương thích Java 17; JDK 21 là lựa chọn phù hợp khi phát triển. Nếu máy đang dùng Java 24 và chạy được bản JAR, không cần cài thêm chỉ để chạy thử. Nếu lệnh không được nhận diện, kiểm tra JAVA_HOME và PATH, rồi mở lại terminal.

2. Chạy ngay bằng một tệp

Nhấp đúp CHAY-UNG-DUNG.cmd. Đợi xuất hiện Started Application, rồi mở:

http://localhost:8081

Giữ cửa sổ lệnh mở. Đăng nhập bằng tài khoản trong README. Dùng cửa sổ ẩn danh hoặc trình duyệt khác để kiểm tra một vai trò khác cùng lúc; các tab cùng hồ sơ trình duyệt chia sẻ phiên.

Bản chạy nhanh dùng H2 dạng tệp, tự tạo database và dữ liệu mẫu; chưa cần bật MySQL. Dữ liệu lưu tại backend\data, còn nguyên sau khi tắt/mở ứng dụng. Không xóa thư mục này nếu cần giữ dữ liệu.

Dừng bằng Ctrl+C. Không chạy hai backend đồng thời với cùng tệp H2. Nếu cổng 8081 bận, dừng phiên UniDesk cũ hoặc mở PowerShell tại thư mục backend và chạy:

java -jar ..\release\student-manager-2.0.0.jar --spring.profiles.active=demo --server.port=8082

Sau đó truy cập http://localhost:8082.

3. Chạy với MySQL

H2 và MySQL là hai nguồn dữ liệu riêng. Chuyển cấu hình không tự chuyển dữ liệu đã nhập từ nguồn này sang nguồn kia.

  1. Bật dịch vụ MySQL 8.x và mở MySQL Workbench.
  2. Mở database\TAO-DATABASE.sql, thay CHOOSE_A_NEW_PASSWORD bằng mật khẩu bạn chọn, rồi chạy bằng tài khoản quản trị MySQL. Không dùng database của dự án cũ.
  3. Mở PowerShell tại thư mục dự án:
Set-Location D:\student-manager-v2
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\CHAY-MYSQL.ps1

Lệnh trên chỉ cho phép chạy tệp script trong tiến trình PowerShell đó; không thay chính sách của máy. Bạn cũng có thể chạy thủ công các lệnh dưới đây.

  1. Nhập tên tài khoản MySQL student_v2 và mật khẩu đã chọn.
  2. Với database mới, nhập YES khi được hỏi tạo dữ liệu mẫu. Flyway tự tạo bảng; không import thêm migration bằng tay.
  3. Đợi backend khởi động và mở http://localhost:8081.

Cách chạy thủ công, không dùng script:

Set-Location D:\student-manager-v2\backend
$env:DB_USERNAME = "student_v2"
$dbSecret = Read-Host "Mat khau MySQL" -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new("", $dbSecret).Password
$env:DB_URL = "jdbc:mysql://localhost:3306/student_manager_v2?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Ho_Chi_Minh"
$env:APP_SEED = "true"
java -jar ..\release\student-manager-2.0.0.jar --spring.profiles.active=mysql --server.port=8081

APP_SEED=true chỉ khởi tạo mẫu khi bảng users trống. Sau lần đầu, có thể đặt false. Đừng tự xóa users để khởi tạo lại trên database đang có dữ liệu.

Chế độ mặc định chỉ lắng nghe trên máy đang chạy (127.0.0.1). Triển khai Internet cần cấu hình HTTPS, cookie bảo mật, tài khoản riêng, giới hạn thử đăng nhập và quy trình vận hành. Bản này phục vụ phát triển và demo đồ án trên máy.

4. Mở và sửa mã nguồn

Backend trong IntelliJ

Mở backend\pom.xml bằng IntelliJ và chọn Open as Project. Chọn JDK phù hợp trong Project SDK, chờ Maven tải thư viện. Chạy lớp vn.studentmanager.Application.

Mặc định backend chạy cổng 8080, dùng profile demo. Trong Run Configuration, đặt Working directory là thư mục backend để dùng cùng vị trí backend\data. Dừng bản JAR trước để tránh khóa tệp H2.

Muốn dùng MySQL trong IntelliJ: đặt active profile mysql, khai báo DB_USERNAME, DB_PASSWORD, DB_URL và APP_SEED trong Run Configuration. Không ghi mật khẩu vào mã nguồn.

Frontend trong VS Code

Cần Node.js từ 20.19 trở lên; có thể dùng Node 22 hoặc 24. Mở thư mục frontend bằng VS Code rồi chạy PowerShell:

Set-Location D:\student-manager-v2\frontend
npm.cmd ci
npm.cmd run dev

Mở http://localhost:5173. Vite chuyển /api tới backend cổng 8080. Giữ cả hai tiến trình chạy. Nếu backend đang chạy cổng 8081, dừng bản JAR và chạy backend cổng 8080, hoặc sửa target trong frontend\vite.config.js cho đúng.

5. Build lại sau khi sửa

Dừng bản JAR đang chạy, nhấp đúp BUILD-LAI.cmd. Script sẽ:

  1. Cài đúng phiên bản frontend theo package-lock.json.
  2. Build React và chép vào tài nguyên tĩnh của backend.
  3. Chạy mvnw.cmd clean verify, gồm các kiểm thử tự động.
  4. Cập nhật JAR trong thư mục release.

Cần mạng ở lần build đầu để tải npm/Maven. Khi báo thành công, chạy lại CHAY-UNG-DUNG.cmd. Nếu build lỗi, giữ nguyên thông báo để sửa; không bỏ qua kiểm thử.

Chạy kiểm thử backend riêng:

Set-Location D:\student-manager-v2\backend
.\mvnw.cmd test

Kiểm thử dùng H2 trong bộ nhớ riêng và không đụng database đang chạy của bạn. Backend dùng Spring JDBC với câu SQL có tham số; không sử dụng JPA trong phiên bản mới này.

6. Nhập/xuất CSV với Excel

  • Trang Quản lý sinh viên → Nhập CSV → Tải CSV mẫu.
  • Giữ tiêu đề cột, lưu định dạng CSV UTF-8, dấu phẩy phân cách.
  • class_id phải là ID lớp có thật. Xem ID bằng API /api/admin/catalog/classes khi đang đăng nhập ADMIN, hoặc cột ID trong trang danh mục lớp.
  • Ngày theo yyyy-mm-dd; giới tính MALE/FEMALE/OTHER; trạng thái STUDYING/PAUSED/LEFT/GRADUATED.
  • Mỗi lần nhập tối đa 200 dòng. Một dòng lỗi thì toàn bộ lần nhập được hoàn tác, không tạo dữ liệu dở dang.
  • Mật khẩu ban đầu dùng chung cho đợt nhập chỉ để cấp lần đầu; từng người dùng bắt buộc đổi trước khi sử dụng.
  • Nút Xuất CSV xuất các dòng khớp tìm kiếm/bộ lọc, không chỉ trang đang nhìn thấy.
  • Không hỗ trợ trực tiếp tệp .xlsx; hãy lưu thành CSV UTF-8 trước khi nhập.

7. Sao lưu và phục hồi

H2: dừng ứng dụng hoàn toàn rồi sao chép cả thư mục backend\data tới nơi lưu trữ khác. Khi phục hồi, dừng ứng dụng, sao lưu dữ liệu hiện tại và thay bằng bản đã lưu. Giữ bản dữ liệu và phiên bản mã nguồn tương ứng.

MySQL: dùng Data Export của MySQL Workbench để xuất student_manager_v2 gồm cấu trúc và dữ liệu. Khi thử phục hồi, nhập vào một database trống riêng rồi đổi DB_URL để kiểm tra. Bản xuất phải gồm bảng flyway_schema_history. Không chép trực tiếp các tệp vật lý của MySQL đang chạy.

9. Ảnh giao diện thực tế

Phạm vi chức năng và quy tắc nghiệp vụ

Đây là bản đồ án có thể chạy trọn luồng quản lý hồ sơ, học phần và điểm; không phải toàn bộ hệ thống vận hành của một trường đại học. Các quy tắc điểm là quy ước minh họa của dự án, cần đối chiếu yêu cầu giảng viên trước khi dùng làm quy chế trường.

Vai trò

Vai trò Quyền
ADMIN Danh mục, hồ sơ, lớp học phần, đăng ký thay sinh viên, điểm, chốt/mở điểm, tài khoản, nhật ký
TEACHER Chỉ lớp được phân công; xem danh sách, nhập/sửa điểm khi chưa chốt, chốt điểm khi đủ điều kiện
STUDENT Xem hồ sơ mình; tra cứu lớp mở, đăng ký/hủy; xem điểm đã công bố của mình

Quyền được kiểm tra ở backend. Giấu nút ở giao diện không phải cơ chế bảo vệ duy nhất. Có phiên cookie HttpOnly, SameSite=Lax và CSRF cho thao tác thay đổi dữ liệu. Mật khẩu băm BCrypt. Mật khẩu mới ít nhất 12 ký tự và tối đa 72 byte UTF-8.

Đã triển khai

  • Khoa, ngành, lớp hành chính, môn học/tín chỉ, học kỳ: thêm/sửa/xóa có kiểm tra liên kết.
  • Sinh viên: thông tin liên hệ, ngày sinh, giới tính, lớp và trạng thái đang học/bảo lưu/thôi học/tốt nghiệp.
  • Giảng viên: thông tin liên hệ, khoa và liên kết tài khoản.
  • Tạo sinh viên/giảng viên đồng thời tạo tài khoản trong một giao dịch; lỗi thì hoàn tác.
  • Tên đăng nhập lấy từ mã hồ sơ chuyển chữ thường. Sửa mã hồ sơ sau này không tự đổi tên đăng nhập đã cấp.
  • Quản lý tài khoản: cấp lại cho hồ sơ chưa có tài khoản, reset mật khẩu, khóa/mở khóa, xóa riêng tài khoản.
  • Khóa/xóa/reset/đổi mật khẩu làm phiên cũ mất quyền ở yêu cầu API kế tiếp; không giả định rằng đóng giao diện trên máy người dùng có thể xóa dữ liệu họ đã xem.
  • Tài khoản mới/reset bắt buộc đổi mật khẩu; người dùng được tự đổi mật khẩu sau khi xác minh mật khẩu hiện tại.
  • Không khóa/xóa ADMIN qua chức năng quản trị này, tránh mất tài khoản quản lý cuối cùng.
  • Lớp học phần: chọn môn/học kỳ/giảng viên, sĩ số, phòng, lịch mô tả, trạng thái, tỷ trọng.
  • Đăng ký: kiểm tra sinh viên đang học, lớp mở, không vượt sĩ số, không đăng ký hai lớp của cùng môn trong cùng học kỳ.
  • Khóa hàng dữ liệu sinh viên và lớp trong giao dịch để bảo vệ đăng ký đồng thời.
  • Hủy chỉ khi lớp đang mở, chưa chốt và chưa có bất kỳ bản ghi điểm. Giữ lịch sử đăng ký đã hủy.
  • Điểm TX1, TX2, KTHP: từ 0 đến 10, tối đa 2 chữ số thập phân; nhập đủ ba thành phần.
  • Tổng tỷ trọng 100%; không sửa tỷ trọng khi đã có điểm. Không đổi tín chỉ của môn đã có lịch sử đăng ký.
  • Chốt điểm cần lớp đã đóng đăng ký và mọi đăng ký đang hoạt động đã có điểm.
  • Giảng viên chỉ nhập/chốt lớp mình phụ trách. Chỉ ADMIN mở lại điểm, bắt buộc lý do.
  • Sửa điểm đã có bắt buộc lý do. Nhật ký ghi người sửa, thời điểm, điểm cũ/mới.
  • Sinh viên chỉ thấy điểm sau khi chốt; mở lại thì tạm ẩn điểm khỏi bảng điểm và GPA đến lần chốt tiếp theo.
  • Tổng quan theo vai trò, lọc danh sách lớp theo học kỳ, tìm kiếm/sắp xếp/phân trang phía trình duyệt.
  • Nhập sinh viên CSV trong giao dịch, xuất CSV cho các bảng.
  • Nhật ký 500 thao tác gần nhất; quy trình sao lưu/khôi phục bằng tệp H2 hoặc MySQL Workbench.

Quy tắc xóa

Đối tượng Xử lý
Chỉ tài khoản Gỡ liên kết rồi xóa tài khoản; giữ hồ sơ, đăng ký và điểm
Sinh viên chưa có lịch sử đăng ký Sau xác nhận, xóa hồ sơ và tài khoản liên kết cùng giao dịch
Sinh viên đã có lịch sử, kể cả đã hủy Chặn xóa hồ sơ; có thể khóa/xóa riêng tài khoản hoặc chuyển trạng thái học tập
Giảng viên đang phụ trách lớp Chặn xóa hồ sơ; chuyển phân công trước
Giảng viên chưa có lớp phụ trách Xóa hồ sơ và tài khoản sau xác nhận
Danh mục được sử dụng/lớp có đăng ký Không xóa; trả thông báo xung đột

Khóa tài khoản và trạng thái học tập là hai thuộc tính riêng. Ví dụ bảo lưu sẽ ngăn đăng ký mới, nhưng không tự khóa quyền xem thông tin. ADMIN quyết định khóa tài khoản khi cần.

Tính điểm và GPA

Tổng kết = (TX1 × tỷ trọng TX1 + TX2 × tỷ trọng TX2 + KTHP × tỷ trọng KTHP) / 100. Làm tròn HALF_UP đến 2 chữ số.

Tổng kết đã làm tròn Điểm chữ Điểm hệ 4
8.50–10 A 4
7.00–8.49 B 3
5.50–6.99 C 2
4.00–5.49 D 1
Dưới 4.00 F 0

GPA = tổng (điểm hệ 4 × tín chỉ) / tổng tín chỉ được tính; bao gồm môn F. Chỉ lấy đăng ký ACTIVE đã được chốt và có điểm. GPA học kỳ tính các lần học trong học kỳ đó. GPA tích lũy chọn lần có tổng kết cao nhất của từng mã môn, mỗi môn chỉ tính một lần. Tín chỉ đạt là tín chỉ của môn có điểm A/B/C/D theo cùng phạm vi. Chưa có điểm thì GPA hiển thị “—”, không giả thành 0.

Giới hạn đã xác định

  • Lịch học là văn bản, chưa kiểm tra trùng tiết/phòng/giảng viên.
  • Chưa có môn tiên quyết, khung chương trình theo khóa, hạn mức tín chỉ hoặc đợt đăng ký tự động theo ngày.
  • Chưa xử lý điểm liệt, vắng thi, miễn học, học phần không tính GPA và quy tắc riêng từng trường.
  • Chưa có tài liệu học phần, học phí, thanh toán, điểm danh, thông báo email, phúc khảo hoặc xét tốt nghiệp tự động.
  • Chưa có quên mật khẩu qua email; người dùng liên hệ ADMIN.
  • CSV tương thích Excel; không đọc trực tiếp XLSX.
  • Các bảng tải dữ liệu để tìm kiếm/phân trang ở client; phù hợp dữ liệu đồ án, chưa tối ưu cho hàng trăm nghìn hồ sơ.
  • Dùng Spring JDBC, không phải JPA. React JavaScript/CSS, không bắt buộc TypeScript/Tailwind/JWT như PDF mẫu.
  • H2 là chế độ chạy nhanh. Có migration/cấu hình MySQL, nhưng chưa kiểm thử trên MySQL thật trong môi trường xây dựng này.
  • Chưa đánh giá tải lớn, kiểm thử xâm nhập hay triển khai Internet. Chế độ mặc định chỉ truy cập trên máy cục bộ.

API và tổ chức mã nguồn

Base URL khi chạy bản JAR: http://localhost:8081/api. Khi phát triển: frontend5173 proxy backend8080.

Xác thực

GET /auth/csrf lấy token và tên header. POST /auth/login dùng form-urlencoded gồm username/password và header CSRF. Sau đăng nhập lấy CSRF mới. Các yêu cầu thay đổi dữ liệu gửi CSRF và cookie phiên; không dùng JWT. GET /auth/me, POST /auth/logout, POST /auth/password (oldPassword, newPassword).

1. Dùng bản mới trên Windows

  1. Tắt ứng dụng cũ bằng Ctrl+C tại cửa sổ đang chạy. Không chạy đồng thời hai bản.
  2. Sao lưu thư mục ứng dụng cũ, đặc biệt backend/data. Đây là dữ liệu H2 của cách chạy mặc định bằng CHAY-UNG-DUNG.cmd.
  3. Giải nén ZIP mới ra thư mục mới, không chạy trực tiếp trong ZIP.
  4. Nếu muốn giữ dữ liệu đã nhập: khi cả hai bản đều đã tắt, sao chép toàn bộ backend/data từ bản cũ sang đúng backend/data của bản mới, trước khi chạy bản mới. Không lấy thư mục target thay cho data. Nếu dùng MySQL từ trước, giữ cấu hình MySQL và sao lưu database MySQL thay vì chép H2.

  6. Nếu trình duyệt còn hình cũ, nhấn Ctrl+F5. Tài khoản và dữ liệu cũ được giữ khi chép đúng data. Với database mới tại máy, tài khoản demo vẫn dùng như hướng dẫn Windows.

Không thay đổi migration V1 hoặc xóa database để cập nhật giao diện.

3. Hiểu đúng cách triển khai

Render chạy cả giao diện React đã build và backend Spring Boot trong một Docker Web Service. Không tạo Static Site riêng. MySQL đặt trên Aiven. Không cần bật máy cá nhân, không cần chạy file .cmd hoặc mở tunnel sau khi deploy xong.

Render Free không chạy liên tục không ngủ: sau 15 phút không có truy cập, dịch vụ có thể ngủ; lần mở lại thường mất khoảng một phút. File ghi vào ổ đĩa Render sẽ mất khi restart/redeploy/ngủ. Vì thế không dùng H2 file trên Render. Nếu cần phục vụ liên tục, chọn instance trả phí phù hợp; gói miễn phí phù hợp trình diễn đồ án.

Aiven hiện có MySQL Free 1 GB dung lượng, không có hạn sử dụng cố định; vẫn có giới hạn và có thể bị tắt khi không hoạt động. Chọn đúng Free, không nhầm gói trial hoặc gói trả phí. Chính sách có thể thay đổi, kiểm tra màn hình giá trước khi tạo dịch vụ.

Dữ liệu trên máy không tự chuyển lên mạng. Hướng dẫn dưới đây tạo database online mới, ban đầu chỉ có một quản trị viên. Không đưa backend/data hoặc mật khẩu lên GitHub. Muốn mang toàn bộ dữ liệu H2 hiện có lên MySQL cần một bước chuyển dữ liệu riêng; chức năng CSV sinh viên không phải bản sao lưu toàn hệ thống.

4. Tạo MySQL trên Aiven

  1. Mở https://console.aiven.io/ và tạo/đăng nhập tài khoản.
  2. Tạo project nếu được yêu cầu, chọn tạo dịch vụ MySQL và gói Free. Chọn vùng gần Render nếu gói cho phép.
  3. Đợi trạng thái Running. Trong trang Overview / Connection information, ghi lại: Host, Port, Database name, User, Password. Dùng đúng port được cấp; không mặc định cho rằng đó là 3306.
  4. Database thường tên defaultdb, user thường avnadmin; lấy giá trị thực trên tài khoản của bạn.
  5. Tải CA certificate trong thông tin kết nối. Mở file .pem bằng Notepad và giữ toàn bộ nội dung từ BEGIN CERTIFICATE đến END CERTIFICATE. Đây là chứng chỉ CA, không phải private key.
  6. Nếu đã giới hạn IP truy cập database, cho phép các dải outbound IP của Web Service Render (xem trang service Render → Connect/Outbound). Nếu chưa giới hạn, dùng mặc định để kết nối lần đầu rồi thiết lập theo nhu cầu.

5. Đưa mã nguồn lên GitHub

Cách dễ trên Windows: dùng https://desktop.github.com/ .

  2. Mở thư mục repository vừa tạo trong Explorer. Chép nội dung bên trong student-manager-v2 vào đó: ở gốc phải thấy Dockerfile, render.yaml, frontend, backend, deploy. Không lồng thêm một tầng student-manager-v2.
  3. Giữ file .gitignore đi kèm. Không đưa data, .env, certificate, node_modules, target hay release JAR lên GitHub. Gitignore đã loại chúng; kiểm tra danh sách Changes trước khi commit.

6. Tạo Web Service trên Render

  1. Đăng nhập https://dashboard.render.com/ . Chọn New → Web Service, kết nối GitHub và chọn repository vừa tạo.
  2. Đặt Name tùy ý, ví dụ unidesk-haui. Chọn branch đã push (thường main).
  3. Language/Runtime: Docker. Root Directory: để trống nếu Dockerfile nằm ở gốc. Dockerfile Path: ./Dockerfile. Chọn region gần database và Instance Type Free để thử.
  4. Không nhập lệnh npm start hay java vào Build/Start Command: Dockerfile và entrypoint đã lo phần này. Nếu có Docker Command, để trống.
  5. Mở Environment Variables, thêm chính xác bảng sau. Nhập giá trị thô, không bọc dấu nháy; không nhập mật khẩu vào mã nguồn.

Docker sẽ đọc file ở /etc/secrets/mysql-ca.pem và tạo truststore tự động. Nếu giao diện chưa cho thêm trước lần deploy đầu, tạo service, bổ sung Secret File ngay trong Environment, rồi chọn Save, rebuild and deploy.
  2. Trong Advanced/Settings đặt Health Check Path: /api/health. Render tự cấp PORT; ứng dụng nhận PORT và lắng nghe trên 0.0.0.0, không cần đặt SERVER_PORT.
  3. Chọn Deploy Web Service. Lần đầu cần tải dependency và build Java/React, có thể mất vài phút. Theo dõi Logs đến khi Live.
  4. Mở URL https://.onrender.com mà Render cấp. Kiểm tra /api/health trả {"status":"UP"}.
  5. Đăng nhập bằng ADMIN_USERNAME và ADMIN_PASSWORD đã đặt. Ứng dụng yêu cầu đổi mật khẩu trước khi dùng. Không dùng Admin@2026Demo trên database online mới.

Tài khoản khởi tạo chỉ tạo khi bảng users trống. Deploy lại hoặc thay biến ADMIN_PASSWORD sẽ không đổi mật khẩu của tài khoản đã tồn tại. Ghi nhớ mật khẩu mới sau lần đổi đầu tiên. Không xóa bảng users để reset.

Nếu thích Blueprint, file render.yaml đã có sẵn: New → Blueprint → chọn repository → nhập các biến sync:false. Tuy nhiên vẫn phải thêm Secret File mysql-ca.pem trong service rồi deploy lại. Với lần đầu, cách Web Service thủ công ở trên dễ theo dõi hơn.

7. Nhập dữ liệu và sử dụng

Database online mới không có dữ liệu demo. Tạo theo thứ tự: Khoa → Ngành → Lớp hành chính, rồi Giảng viên, Sinh viên, Môn học, Học kỳ, tiếp theo Lớp học phần → Đăng ký học → Điểm. Cấp tài khoản cho hồ sơ sinh viên/giảng viên trong mục Tài khoản nếu cần.

Sau khi online, có thể tắt máy cá nhân. Dữ liệu nằm trong MySQL Aiven và không mất chỉ vì Render deploy lại. Vẫn cần sao lưu database định kỳ; đừng coi CSV sinh viên là backup toàn bộ. Tắt/xóa service Render không tự xóa database Aiven. Xóa database Aiven là thao tác riêng và có thể mất dữ liệu.

Muốn tạm ngừng truy cập: dùng Suspend service trong Render nếu có trên giao diện tài khoản. Không xóa database chỉ để tắt website. Khi cần dùng lại, resume/redeploy dịch vụ.

8. Lỗi thường gặp

Hiện tượng Kiểm tra
Missing /etc/secrets/mysql-ca.pem Thêm đúng Secret File và deploy lại, không chỉ tạo biến môi trường cùng tên.
Communications link failure / timeout Aiven đang Running, đúng Host/Port, kiểm tra IP allowlist và kết nối mạng.
Access denied for user Kiểm tra DB_USERNAME/DB_PASSWORD, không nhầm với tài khoản admin của ứng dụng.
SSL handshake / PKIX / certificate Lấy lại CA đúng của dịch vụ Aiven hiện tại; dùng hostname Aiven, không IP. Giữ sslMode=VERIFY_IDENTITY.
Set ADMIN_PASSWORD… Mật khẩu lần khởi tạo trống hoặc quá ngắn; sửa biến rồi deploy lại.
No open ports / Health check failed Xem lỗi khởi động/database phía trước trong Logs; phải bật profile render, Health Check Path đúng.
Cannot find Dockerfile Dockerfile ở gốc repo; Root Directory và Dockerfile Path phải khớp.
Đăng nhập không giữ phiên Dùng URL HTTPS của Render; cookie của profile render chỉ gửi qua HTTPS.
Trang mở chậm sau thời gian không dùng Đây có thể là lúc Render Free đang thức dậy.
Out of memory / exit 137 Gói RAM thấp; kiểm tra Logs, nâng instance nếu tải vượt khả năng.
Chữ/logo còn như cũ Ctrl+F5; kiểm tra bản build/deploy mới đã Live.

9. Các file cấu hình đã thêm

  • Dockerfile: build React, chạy kiểm thử/build Spring Boot, đóng gói Java 21 runtime.
  • render.yaml: Blueprint mẫu, không chứa mật khẩu.
  • deploy/start-render.sh: nạp chứng chỉ CA, chạy JAR với heap tối đa 256 MB.
  • application-render.properties: nhận PORT, cookie HTTPS, MySQL TLS xác minh hostname, pool tối đa 5 kết nối; tắt seed demo.
  • BootstrapAdmin.java: tạo quản trị viên đầu tiên bằng mật khẩu môi trường, không reset khi restart.
  • Health.java: endpoint kiểm tra database, không công khai thông tin kết nối.

Bản đóng gói được kiểm thử tại môi trường phát triển; chưa deploy vào tài khoản Render/Aiven của bạn. Kiểm tra MySQL/TLS thực tế sẽ diễn ra ở lần deploy của bạn.
